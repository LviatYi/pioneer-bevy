# 地貌 Landform

## 实现方案鸟瞰

Pioneer 的地貌系统用于描述由泥土构成的连续地表形态，包括平原、丘陵、山体、悬崖、洞穴等结构。地貌仅负责描述空间中「泥土与空气的边界」，不负责描述矿脉、岩层、矿物种类等地质信息。

地貌采用 **三维标量场（Scalar Field）** 作为基础表示。

三维标量场可以理解为：对于空间中的任意位置，地貌算法都能够返回一个数值，用于描述该位置相对于泥土表面的状态。约定负值表示泥土内部，正值表示空气，零值表示泥土与空气的边界，即实际地表。

整体实现流程如下：

```text
Landform Generator
可插拔地貌生成算法
    │
    │ sample(position)
    ↓
Base Scalar Field
基础地貌标量场
    │
    │ 叠加玩家/建筑造成的地形修改
    ↓
Final Scalar Field
最终地貌标量场
    │
    │ 在局部空间采样
    ↓
Terrain Chunk Cache
地形区块缓存
    │
    │ 表面提取
    ↓
Triangle Mesh
连续三角网格
    │
    ├── Rendering
    └── Collision
```

## 逻辑表示

Pioneer 的地貌系统需要描述完整的三维泥土实体，而不只是某个平面位置上的地表高度。

因此，地貌不采用传统高度图作为基础逻辑表示，而采用 **三维标量场（Scalar Field）**，它是一种有符号距离场（Signed Distance
Field，SDF）。

### 三维标量场

标量场可以理解为：

> 对空间中的任意一个位置，赋予一个数值。

```text
field(x, y, z) -> value
```

其中，数值的绝对值表示当前位置到最近表面的距离。

Pioneer 约定标量值具有以下基本语义：

```text
field(P) < 0.0    → P 位于泥土内部
field(P) = 0.0    → P 位于泥土表面
field(P) > 0.0    → P 位于空气中
```

例如一个完全平坦、地表高度为 `y = 0.0` 的地貌：

```rust
fn field(position: Vec3) -> f32 {
    position.y
}
```

当前阶段真正重要的只有：

```text
负值 = 泥土
零值 = 表面
正值 = 空气
```

> 地表是标量场的零等值面。
> 洞穴是泥土内部的一块标量值重新变为正值的空间区域。

### 地貌存储

三维标量场描述地貌的 **逻辑模型**，但不意味着运行时需要真正保存整个世界中所有位置的数值。

* 保存在稀疏数据结构中
* 由程序生成算法即时计算
* 只缓存玩家附近的区域
* 在规则三维网格中缓存
* 使用八叉树等层级结构表示
* 从基础生成算法和玩家修改共同计算得到

## 网格生成

三维标量场定义了地貌的连续形状，但无法直接作为渲染几何使用。地貌网格生成负责对标量场进行有限采样，并从中提取 `SDF = 0.0`
的表面，最终生成 Triangle Mesh。

整体流程如下：

```text
Landform SDF
    ↓
规则空间采样
    ↓
SDF Samples
    ↓
Marching Cubes
    ↓
Triangle Mesh
```

### 空间离散

SDF 在逻辑上可以查询空间中的任意位置，但连续空间包含无限多个点，因此实际生成 Mesh 时必须进行 **离散采样**。

离散采样是指按照固定间距，在三维空间中建立规则采样点，三维空间中的八个相邻采样点共同围成一个立方体区域，称为
**Cell（网格单元）**。

每个采样点执行一次地貌查询：

```rust
let sdf = landform.sample(position);
```

由此得到有限的 SDF 数据。

相邻采样点之间的世界距离称为 **采样间距（Sample Spacing）**。采样间距越小，能够表现的地貌细节越丰富，同时采样和网格生成成本也越高。

需要注意：

> Cell 只是用于分析 SDF 的空间单元，并不是实际存在的泥土方块。

显然，Pioneer 的泥土表面仍然可以穿过 Cell 内部的任意位置，因为采样点上的 SDF 并不总是恰好为 0.0。

### 等值面提取

Pioneer 使用 **Marching Cubes** 从离散 SDF 中提取地表。

Marching Cubes 是一种从规则三维标量场中生成等值面三角网格的算法。它逐个检查 Cell 的八个角，根据各采样点位于地表内部还是外部，判断
`SDF = 0.0` 的表面如何穿过该 Cell。

例如一条 Cell 边的两个端点分别为：

```text
Air                      Soil

+1.5 ●────────────────● -0.5
```

由于 SDF 在两端符号不同，可以确定地表穿过了这条边。

算法会根据两端的 SDF 数值，通过 **插值（Interpolation）** 估计零点的位置。插值指根据若干已知采样值估算它们之间的数值或位置。

随后，Marching Cubes 根据 Cell 八个角的正负状态确定三角形的连接方式：

```text
8 个 SDF 样本
      ↓
判断正负状态
      ↓
确定穿过哪些边
      ↓
估算零点位置
      ↓
生成三角形
```

最终所有 Cell 产生的三角形共同构成连续地貌 Mesh。

### 网格区块

地貌不会一次生成整个世界的 Mesh，而是将空间划分为若干 **Chunk（区块）**。

Chunk 是地貌网格生成和更新的空间单位。例如，一个 Chunk 可以包含：

```text
32 × 32 × 32 Cells
```

如果一个方向存在 32 个 Cell，则需要 33 个采样点：

```text
●──●──●── ... ──●
   32 Cells
   33 Samples
```

因此一个 `32³` Cell 的 Chunk 需要覆盖 `33³` 个 SDF 采样位置。

Chunk 在此处仅表示 Mesh 的空间管理单位，并不意味着 SDF 必须按同样的 Chunk 形式持久化保存。

一期可以采用：

```text
需要生成 Chunk
      ↓
临时采样 SDF
      ↓
运行 Marching Cubes
      ↓
生成 Mesh
```

### Chunk 边界

相邻 Chunk 的公共边界必须使用完全一致的世界空间采样位置。

例如：

```text
Chunk A             Chunk B

●──●──●──●────────●──●──●
         ↑
       公共边界
```

边界两侧如果在不同位置独立采样，或者使用不同的计算规则，生成的零等值面可能无法完全重合，从而产生可见裂缝。

因此 Chunk 的采样坐标应由统一的整数网格坐标和固定采样间距推导，而不应通过逐次浮点累加确定。

相邻 Chunk 可以分别生成自己的 Mesh，但公共边界必须保证：

* SDF 查询位置一致；
* SDF 值一致；
* 表面交点计算规则一致。

这使多个独立 Chunk 最终能够组成视觉上连续的地貌。

### 网格输出

Marching Cubes 的最终结果是一组：

```text
Vertices
顶点

Indices
三角形连接关系
```

并进一步计算 **Normal（法线）**。法线是表示表面朝向的方向向量，主要用于光照计算和地貌视觉表现。

生成结果随后交由后续系统使用：

```text
Landform SDF
     ↓
Sampling
     ↓
Marching Cubes
     ↓
Triangle Mesh
     ├── Rendering
     └── Collision
```

因此，Triangle Mesh 是三维标量场的派生结果，而不是 Pioneer 地貌的逻辑表示本身。
